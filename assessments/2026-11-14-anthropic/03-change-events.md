### Event A: [Claude Code email-leak incident — GitHub issue #107757. Report label: SAME VENDOR, DIFFERENT PRODUCT. What it evidences: vendor-level notification and fix behavior under §4.3, not API operational posture.]
- **Event:** Reported Nov 5, 2026 on the anthropics/claude-code public issue tracker (issue #107757), detected and announced by a customer, not by the vendor: a user reports that Claude Code v2.1.318 placed his account email address in the User-Agent header of web-search requests, disclosing it to third parties. An Anthropic commenter states on the thread that a built-in mod, cc-plugin-privacy, was introduced in v2.1.317 to deterministically block this class of disclosure, enabled by default and disableable via /plugins. A later commenter reports that on v2.1.319 the mod did not block a shell command carrying the email in a User-Agent header, in a loopback probe in which nothing left his machine. Reporter accounts; not independently verified.
- **Inventory updated:** Sat Nov 14, 2026 — no entry changed. Claude Code is not an inventoried component of the assessed chain; the event is recorded as vendor-level evidence only, per the report label above.
- **Revalidation triggered:** None for the assessed chain. Scoping decision recorded Sat Nov 14, 2026: the affected component sits outside the inventory, so no revalidation of the summarizer or drafter legs is triggered; the event evidences vendor-level detection and disclosure behavior.
- **Behavior comparison:** Not run, stated plainly per §4.3: the assessed components are API model calls, and no comparable behavior test exists for a client-side header defect in a different product.
- **Rubric impact:** None. The six Gate 1 scores rest on the assessed product's documented record. The event is carried into the assessment report as a vendor-level finding on detection and disclosure: the defect was customer-detected and publicly reported rather than vendor-announced, the fix shipped inside a version with no announcement this assessment could cite, and the fix's completeness is contested on the vendor's own tracker.
- **Closure:** Still open — the vendor's fix claim and a user's counter-report of a shell-command bypass stand unresolved on the thread, and no evidence available to this assessment settles whether the fix covers that path. Ruled by Paulo, Sat Nov 14, 2026 · **Approver:** Paulo
